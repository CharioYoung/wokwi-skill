# Microduck — 双足鸭形机器人 · 两张图纸

高 25 cm、宽 14 cm、800 g、15 个自由度。图纸拆成两张，各管一件事：

| 图纸 | 文件 | 回答什么 |
| --- | --- | --- |
| **外观与 3D 打印图** | `shell.html` | 打出来长什么样、怎么打、器件装不装得下 |
| **器件接线图** | `internals.html` | 里面有什么、每个脚接到哪、线怎么走 |

两张图不共用镜头，也不共用相机 —— 它们共用的是**事实**：

- `src/hardware.js`：哪块板、什么插座、几号脚、脚上是什么网（两张图和校验脚本都读它）
- `src/model.js` + `src/fit.js`：几何与壁厚（外观图的间隙表、3D 线束的穿模检查用）

所以改一个插座脚数，接线图的针、网表、BOM 和校验会一起变，不会出现
"图上标 J5.3、表里写 J5.4"。

合在一页的时候做不好：外壳一剖就看不出外观，不剖又看不见器件，
两头都不彻底。旧的三合一评审台（姿态 / 步态 / 配色 / 总线泳道图）保留在
`review.html`，当演示用。

## 跑起来

```bash
node microduck/serve.mjs      # 默认 http://localhost:8099/
```

**必须走 HTTP。** 浏览器的 ES 模块在 `file://` 下会被 CORS 拦掉。

## 图纸 1 · 外观与 3D 打印（`shell.html`）

**看外观**

- 自由旋转（拖拽 / 滚轮 / 右键平移 / 双击复位），四视图用 scissor 切一块画布画四个机位。
- 尺寸标注是按实测包围盒算的：140 × 214 × 250 mm，另标分模面与壁厚。

**指导打印**

分件表 25 件，除材料与层高是人定的，其余都是量出来的：

| 量出来的 | 怎么算 |
| --- | --- |
| 尺寸 | 该件网格的包围盒（分件按高度带裁剪） |
| 摆向 | 六个轴向姿态里挑"高度最小 + 悬垂最少 + 底面最大"的 |
| 支撑 | 法线朝下且比 45° 更平的面积占比 > 6% → 树状，> 2% → 局部，否则免支撑 |
| 克数 | 壳件 = 表面积 × 2.4 mm 壁厚；实心件 = 体积 × 95%；薄壁附件按 1.2 mm |
| 热床 | 220 × 220 × 250 mm（Bambu A1 / P1S） |

当前：25 件、材料 PETG + TPU 95A/85A、主体 **622 g**（含轮滑底板选配 812 g）、
超床 0 件、需支撑 21 件。

点任一行 → 其余件压暗，只留这一件；上身壳 / 下身壳会按分模面 y = 75.5 mm
真的切开（两个 clipping plane 夹成一条带），否则件 1 和件 2 长得一模一样。

**器件容纳**

「腔体」模式：外壳降到 11% 不透明，单独画一层内壁线框（与壁厚同源），
器件按体积出现，右侧切到容纳表 —— 每件到内壁的最小间隙，按四个角点取最差的一个。

当前 47 件全部为正，最紧的是主控板 **2.9 mm**，其次是两颗 NFC 读卡器 3.6 mm。
点一行会把相机送到那件器件旁边。

> 内壁是"外壁剖面 - 2.4 mm"的旋转体近似，不是布尔挖空。所以这是**净空检查**，
> 不是完整的干涉分析：螺钉柱、卡扣、加强筋都还没有建模。

## 图纸 2 · 器件接线图（`internals.html`）

这一页没有 three，也没有外壳。它就是一张**装配台的照片**：板子平铺在桌面上，
插座朝外，线从这根针拉到那根针。器件是按实物画的 —— 深绿阻焊、金色焊盘、
金属屏蔽罩、丝印、安装孔、JST 壳体、白色舵盘 —— 和 Wokwi 一个路子。

**为什么不做成 3D 剖视**

塞进壳体里画，器件只能露出一个角，脚号和网名全被挡掉；而接线图要回答的
恰恰是"第几脚接哪儿"。所以两张图彻底分开：外观图管"装不装得下"，
这一页管"接得对不对"。器件尺寸只作为约束参与外观图的间隙核算，不进这张图。

**数据怎么流**

```
hardware.js ──► netlist.js ──► diagram.js ──► internals.html
（插座/网名）   （引脚→网）    （布局+布线+SVG）
        └──────► parts2d.js ──┘
                 （器件插画）
```

`netlist.js` 是纯数据（没有 three、没有 DOM），所以 `check-diagram`、
`shot-diagram` 和页面读的是同一份网表。改一处脚号，三处一起变。

**布局**

- 13 件器件 + 15 个舵机各有自己的盒子；插座按 `SIDES` 表**贴在自己那条边上**，
  在边上平均分布 —— 把 24 脚的 FPC 放到远离摄像头的一侧，线就要横穿整块主控板。
- 舵机板 16 个 3P 口是硬约束：8 个排右边、7 个排下边，板子因此被撑到 272 × 306 px，
  针距压到 6.5 px 才排得下。
- 器件标题**写在盒子上沿以外**，并且按上方空档自动决定写一行还是两行 ——
  顶边挂了插座的板子（主控 / 电源 / 舵机）标题还要再跳高一层，否则
  "舵机总线板"正好压住 S0/S1。这条现在有坐标校验兜着。

**布线**

8 px 栅格 + 二叉堆 A*，4 邻域，代价 = 步长 + 拐弯惩罚 7 + 已被占用代价 1.15：

- 硬避障：器件包围盒内缩 5 px 全部 `blocked`，画布最外一圈也 `blocked`（贴边的线会被裁掉）；
- 软避障：`used[]` 记占用，后来的线主动让开，于是自然形成并排线束而不是叠成一坨；
- 端点不在栅格上，直接连会得到斜线，所以两端各补一个 L 形接头；
- 24 芯 FPC 走单独一条路：手写 Z 形主干 + **正确斜接**（交点方向取上一段的，
  取错了会在拐角回头，24 根就糊成一片网点），两端各留 120 px 直段，扇出用直线。

当前 87 段线 + 1 条 24 芯排线，55 个插座 216 个针脚。

**看得清**

- 滚轮缩放、拖拽平移、双击复位（改 `viewBox`，不重排）；
- 点插座 → 右边出逐脚表（脚号 / 网名 / 接到哪），`#` 开头的网显示"板内铜皮"；
- 点网名 → 全链高亮，其余压暗；
- 底部 60 条网的完整网表，可过滤；另有 BOM 页签；
- 侧栏按 7 路总线过滤；脚号可开关（24 脚 FPC 上只标两位编号）。

## 校验

```bash
node tools/check-diagram.mjs   # 接线图：盒子 / 贴边 / 端点 / 穿板 / 轴对齐 / 标题牌 / 网不漏
node tools/check-pins.mjs      # 3D 线束：引脚贴壳、网表自洽、不穿器件、端点落在脚上
node tools/check-print.mjs     # 上床、料量、容纳间隙（有负的就退 1）
node tools/check-internals.mjs # 内部件不超出壳体内表面
node tools/check-pages.mjs     # 页面 id / import / THREE API 静态体检
node tools/api-check.mjs       # three API 与 WebGLRenderer 方法
node tools/check-wiring.mjs    # 泳道图几何
```

出图（这台机器上浏览器无头模式起不来，所以直接吃导出的 SVG）：

```bash
node tools/shot-diagram.mjs .dev/diagram.png                        # 整张 1480×980
node tools/shot-diagram.mjs .dev/c.png --scale=2 --crop 560,40,480,240   # 局部放大
```

`check-diagram` 的判据全是坐标，不看图：

- 28 个器件盒子互不重叠；
- 55 个插座必须贴在自己板子的那条边上，216 根针必须落在壳体里；
- 87 段线的两端必须落在它声明的那两个针上（≤2 px）；
- 没有一段线穿过器件本体，没有斜段，没有越出画布；
- 60 条可见网一条都不能漏画，也不能画出网表里没有的"幽灵线"；
- 13 个器件标题牌都不许压到器件，也不许互相压 ——
  这条是补出来的：标题原来贴在盒子上沿 -21，正好落在顶边插座上，
  "舵机总线板"盖住 S0/S1，目视很难发现，一量就露。

## 三个坑

写在这里，因为都是同一类错：**几何错了画面依然"成立"，只有量坐标才发现。**

**眼睛**：规格写"单目摄像头"，但脸上不能只长一只眼。所以做成双眼：左眼是真摄像头，
右眼是同款镜筒的红外补光 + 对称装饰。镜座做成外小内大的锥形，内端埋进壳里。

**脚**：`ExtrudeGeometry` 在 XY 平面挤出，`rotateX(-90°)` 把形状 +Y 送到 -Z，而机头在 +Z ——
脚尖于是朝着屁股。修法是落地后再 `rotateY(180°)`。验证不靠看图：

```
footShellL z: -1.87 .. 5.71 | ankle z 0.15
  前伸 5.56  /  后伸 2.02  => 脚尖朝 +Z（前）OK
```

**舵机数**：规格写 15 自由度（每腿 5），模型里原来只有髋俯仰 + 膝两个，
数一数就知道对不上。补了髋偏航、踝俯仰、踝侧倾 6 个，内部图里才数得出 15 个舵机。

## 改比例

`src/model.js` 顶部有 `PROPORTION`，整机体型都从那里取。改完跑：

```bash
node tools/calibrate.mjs
node tools/check-internals.mjs
node tools/check-pins.mjs
node tools/check-print.mjs
node tools/preview.mjs cream stand out.png
```

壁厚在 `src/fit.js` 的 `WALL`；剖面的关键点与 `model.js` 的 lathe 入参逐点对应，
改剖面要两边一起改（`check-print` 会把负间隙列出来，改漏了会红）。

## 已知限制

- **不是结构 CAD**：有壁厚、有净空检查、有分件与摆向，但没有螺钉柱、卡扣、加强筋、
  拔模角与装配顺序；内腔是"外壁 - 壁厚"的旋转体近似，不是布尔挖空。
- **引脚是几何示意，不是原理图**：脚位、网名、总线类型按规格写的，没从真实
  EDA 工程导入；`check-pins` 验的是"自洽 + 不穿模"，不是电气正确。
- **3D 线束是自动寻路的**，还有 3/2400 个采样点贴着主控板角落擦过（被 `check-pins`
  如实报出来）。真实线束会有扎带和固定点，这里只保证了拓扑与大致走向。
  2D 接线图的走线是栅格 A*，硬避障，穿板 0 / 斜线 0 / 出界 0，但**不按物理比例** ——
  它回答"接哪根针"，不回答"够不够长"。
- **页面本身没有浏览器验收**：本机 Edge 以 `headless` 启动会立刻正常退出
  （code 0），命令行连 `--version` 都不回，puppeteer 拿不到 DevTools 端口。
  所以验证靠 Node 端自写光栅化（`preview.mjs`）+ resvg 直吃 SVG（`shot-diagram.mjs`）
  + DOM stub + 静态体检。2D 接线图的好处正在这里：它就是一段 SVG，
  Node 里能原样渲染成 PNG，图上看得到的和页面上是同一份像素。
  页面留了 `window.onerror` 兜底：出错会把信息打在屏幕上，而不是黑屏。
- 姿态是手调关键帧 + 时间线，不是 MuJoCo 跑出来的策略。
