# Microduck — 双足鸭形机器人 · three.js 评审台

按规格参数化建模的实时 3D 页面：可以自由旋转看外观，也可以把外壳透视或剖开看内部器件与线束，
另有一张总线泳道图说明"哪个器件接到哪个口"。

不是渲染好的图片，是浏览器里真的在跑的 three.js 场景。

```
microduck/
├── index.html          # 评审台页面（UI + canvas + 连接图面板）
├── src/model.js        # 参数化几何：躯干 / 头 / 双眼 / 鸭嘴夹爪 / 腿 / 蹼足 / 内部器件 / 线束
├── src/wiring.js       # 电气连接拓扑（总线泳道图，DOM/SVG）
├── src/app.js          # 场景、灯光、自写轨道相机、四视图、姿态时间线、三种外壳模式
├── vendor/three/       # 内置 three r186（两级 ESM：module + core）
├── tools/
│   ├── preview.mjs      # Node 端光栅化：多视角 / 多姿态 / 内部 / 剖切
│   ├── calibrate.mjs    # 逐姿态量最低点，修 bodyY（防穿地）
│   ├── check-internals.mjs  # 47 个内部件是否都装得进壳里
│   ├── check-wiring.mjs     # 连接图的行距 / 压字 / 连线端点
│   ├── api-check.mjs    # 静态核对用到的 three API 是否都存在
│   ├── shot-wiring.mjs  # 把连接图光栅化成 PNG（DOM stub + resvg）
│   └── shot-web.mjs     # 无头浏览器验收（本机 Edge 会直接退出，未跑通）
└── serve.mjs           # 80 行静态服务器
```

## 跑起来

```bash
node microduck/serve.mjs      # 默认 http://localhost:8099/
```

**必须走 HTTP。** 浏览器的 ES 模块在 `file://` 下会被 CORS 拦掉，直接双击
`index.html` 只会看到一段提示。

## 页面上有什么

**外观**

- 自由旋转：拖拽旋转、滚轮缩放、右键平移、双击复位，带惯性阻尼。
- 四视图：一个 renderer 用 scissor 切成四块画四个机位，四个视角同时可见。
- 四配色：奶油白 / 石墨灰 / 薰衣草紫 / 天空蓝。
- 六种姿态：站立、蹲下、摇摆行走（循环步态）、嘴部抓取、踢球、跌倒爬起。
- 标注：相机 / 右眼 / LiDAR / 鸭嘴夹爪 / 扬声器 / NFC / 电池。
- 轮滑底座、线框、复位视角。

**内部**

- **外观 / 透视 / 剖切** 三种外壳模式。透视把外壳降到 14% 不透明；剖切用 per-material
  clipping 真的切掉靠近观察者的半边外壳，内部件保持完整 —— 剖切面每帧跟着相机转，
  所以从任何角度看，切开的都是挡在眼前的那一半。
- 腔体里摆了 47 个器件：RK3566 主控板 + SoC + eMMC + 无线模组 + 散热片、电源分配板、
  舵机总线板、双 IMU、双 NFC、扬声器、拾音麦、摄像头模组、LiDAR 模组、颈/头/喙舵机、
  以及一根连接头与躯干的内骨架立柱。
- 14 条线束按总线类型分色，带流动脉冲。颜色与连接图一一对应。
- 内部标注另有一套（青色），与外观标注互斥显示。

**连接图**

- 点面板上的「连接图」打开。一行一路总线，左进右出，中间是 RK3566 竖带。
- 电源 / 舵机总线 / MIPI CSI-2 / I2C / I2S / GPIO / 无线，七类总线各有颜色。
- 鼠标移到某一行只保留该路，其余压暗。

## 两个关于"眼睛"和"脚"的坑

写在这里，因为都是同类型的错：**几何朝向错了，画面依然"成立"，只有量坐标才发现。**

**眼睛**：规格写的是"单目摄像头"，但脸上不能只长一只眼 —— 鸭子的脸是左右对称的，
少一只立刻成怪物。所以做成双眼：左眼是真摄像头（后面有 CMOS 模组），右眼是同款镜筒的
红外补光 + 对称装饰。镜座做成外小内大的锥形，内端埋进壳里，凸面上才没有缝。

**脚**：`ExtrudeGeometry` 在 XY 平面上挤出，`rotateX(-90°)` 把形状的 +Y 送到 -Z，
而机头在 +Z —— 于是脚尖朝着屁股，整只鸭子在倒着走。修法是落地后再 `rotateY(180°)`。
验证不靠看图，靠坐标：

```
footShellL z: -1.87 .. 5.71 | ankle z 0.15
  前伸 5.56  /  后伸 2.02  => 脚尖朝 +Z（前）OK
```

## 改比例

`src/model.js` 顶部有 `PROPORTION`，整机体型都从那里取：

```js
export const PROPORTION = {
  totalH: 25,
  bodyBottom: 4.0, bodyTop: 14.6, bodyR: 6.42, bodyDepthK: 1.10,
  hipY: 5.45, thigh: 2.30, shin: 2.10, ankleY: 0.95,
  headCY: 21.1, headR: 3.95,
  footScale: 1.28,
};
```

改完跑一遍：

```bash
node tools/calibrate.mjs                 # 看每个姿态该下沉多少
node tools/check-internals.mjs           # 内部件有没有戳出壳
node tools/preview.mjs cream stand out.png
```

## 关于"穿地"

姿态角是手写的，靠 `calibrate.mjs` 只能对齐静止点；更麻烦的是俯仰叠上偏航之后，
模型会绕一根斜轴转，一侧沉下去 —— 单独量 `bodyY` 是量不出来的。
所以 `app.js` 里有一段 `groundClamp()`：每帧量一次世界空间最低点，往 0 轻轻推。
与其把几十个关节角调到刚好，不如让模型自己贴住地面。

## 已知限制

- 这是**外观 + 装配示意**模型，不是结构 CAD：没有壁厚、拔模、螺丝柱、装配顺序。
  内部器件的位置是按腔体空间摆的，没有做干涉分析（只做了"是否超出壳体内表面"的检查）。
- 姿态是手调关键帧 + 时间线，不是 MuJoCo 里跑出来的策略；页面上演示的是"看起来对"，
  不是 15 自由度的真实运动学解。
- `tools/shot-web.mjs` 在这台机器上跑不通：Edge 以 `headless` 启动会立刻正常退出（code 0），
  puppeteer 拿不到 DevTools 端口，命令行连 `--version` 都不回。所以 WebGL 的实际出图
  没有人眼之外的证据，页面里留了 `window.onerror` 兜底，出错会把信息打在屏幕上而不是黑屏。
- 连接图是拓扑示意图，接口名与速率是按规格写的，不是从真实原理图导入的。
