# Microduck — 双足鸭形机器人 · 两张图纸

高 25 cm、宽 14 cm、800 g、15 个自由度。图纸拆成两张，各管一件事：

| 图纸 | 文件 | 回答什么 |
| --- | --- | --- |
| **外观与 3D 打印图** | `shell.html` | 打出来长什么样、怎么打、器件装不装得下 |
| **器件装配与连线图** | `internals.html` | 里面有什么、每个脚接到哪、线怎么走 |

两张图共用同一份几何（`src/model.js`）和同一份壁厚数据（`src/fit.js`），
所以改一个比例，打印的间隙表和器件的穿模检查会一起变。

合在一页的时候做不好：外壳一剖就看不出外观，不剖又看不见器件，
两头都不彻底。旧的三合一评审台（姿态 / 步态 / 配色 / 总线泳道图）保留在
`review.html`，当演示用。

## 跑起来

```bash
node microduck/serve.mjs      # 默认 http://localhost:8099/
```

**必须走 HTTP。** 浏览器的 ES 模块在 `file://` 下会被 CORS 拦掉。

## 图纸 1 · 外观与 3D 打印（`shell.html`）

**看外观**

- 自由旋转（拖拽 / 滚轮 / 右键平移 / 双击复位），四视图用 scissor 切一块画布画四个机位。
- 尺寸标注是按实测包围盒算的：140 × 214 × 250 mm，另标分模面与壁厚。

**指导打印**

分件表 25 件，除材料与层高是人定的，其余都是量出来的：

| 量出来的 | 怎么算 |
| --- | --- |
| 尺寸 | 该件网格的包围盒（分件按高度带裁剪） |
| 摆向 | 六个轴向姿态里挑"高度最小 + 悬垂最少 + 底面最大"的 |
| 支撑 | 法线朝下且比 45° 更平的面积占比 > 6% → 树状，> 2% → 局部，否则免支撑 |
| 克数 | 壳件 = 表面积 × 2.4 mm 壁厚；实心件 = 体积 × 95%；薄壁附件按 1.2 mm |
| 热床 | 220 × 220 × 250 mm（Bambu A1 / P1S） |

当前：25 件、材料 PETG + TPU 95A/85A、主体 **622 g**（含轮滑底板选配 812 g）、
超床 0 件、需支撑 21 件。

点任一行 → 其余件压暗，只留这一件；上身壳 / 下身壳会按分模面 y = 75.5 mm
真的切开（两个 clipping plane 夹成一条带），否则件 1 和件 2 长得一模一样。

**器件容纳**

「腔体」模式：外壳降到 11% 不透明，单独画一层内壁线框（与壁厚同源），
器件按体积出现，右侧切到容纳表 —— 每件到内壁的最小间隙，按四个角点取最差的一个。

当前 47 件全部为正，最紧的是主控板 **2.9 mm**，其次是两颗 NFC 读卡器 3.6 mm。
点一行会把相机送到那件器件旁边。

> 内壁是"外壁剖面 - 2.4 mm"的旋转体近似，不是布尔挖空。所以这是**净空检查**，
> 不是完整的干涉分析：螺钉柱、卡扣、加强筋都还没有建模。

## 图纸 2 · 器件装配与连线（`internals.html`）

**器件**

外壳退成 6% 的一层影（可关），47 件器件 + 15 个舵机是全部实体。
器件的分类过滤（计算 / 电源 / 驱动 / 传感 / 音频 / 视觉 / 关节）会连带隐藏
对应的插座和线束 —— 因为一条线的两端只要有一端不在，这条线就不该留着。

**引脚**

55 个插座、216 个引脚，每个插座都是一段真实的壳体 + 一排金属针，
针的位置就是从器件包围盒推出来的连接器面上的等距点：

```js
{ id: 'J5', dev: 'mb', label: 'I2C 扩展', type: 'PH20', edge: '-x', along: 1.2,
  pins: ['I2C_3V3', 'GND:i2c', 'I2C_SCL', 'I2C_SDA'] }
```

- 位置从器件包围盒的某个面推出来，所以器件挪了，插头和线跟着走，不用改两处。
- `#VSERVO` 表示板内铜皮 / 器件内部连接 —— 只进表，不画线。
- `GND:power` 表示带域的地。地不分域的话，一颗 GND 会把电池、舵机、摄像头的地
  连成一条横穿机身的线，既不真实也没法看。

**连线**

线束不是画上去的装饰：网表由引脚反推，同一个网名出现在几个脚上，就是几点的链。
每条链先用最近邻 + 2-opt 排一个"最短走法"，再逐段找控制点：

- 默认控制点把中点推向机身内壁（线在真实机器里就是贴壳走的）；
- 如果按内壁推之后路径仍然穿过别的器件，就在一组候选里（更贴壁 / 上下绕 /
  侧向绕 / 绕主板前后沿）挑第一个"采样全程都不进器件"的；
- 芯数 ≥ 8 的组改画扁排线（摄像头的 24 芯 FPC 就是一条带子，不是 24 根圆管）；
- 同一对插座之间的多芯线并成一束，沿切向错开，看起来是一根排线而不是一坨。

当前：60 条网、87 段线 + 1 条 24 芯排线；穿模采样点 3/2400（贴着板角擦过，见下）。

**看得清**

- 点一个插座 → 右下角开一个近摄视口（scissor 第三个视口），pin 号和网名用 DOM
  标在针上：8 脚以内标"号 + 网名"，24 脚的 FPC 只标两位编号。
- 底部逐脚网表，可过滤、可点；点一行跳到起点插座并选中。
- 悬停线束给出起止脚（`S5.3 → JS4.3`），悬停插座给出型号与脚数。

## 校验

```bash
node tools/check-pins.mjs      # 引脚贴壳、网表自洽、线不穿器件、端点落在脚上
node tools/check-print.mjs     # 上床、料量、容纳间隙（有负的就退 1）
node tools/check-internals.mjs # 内部件不超出壳体内表面
node tools/check-pages.mjs     # 页面 id / import / THREE API 静态体检
node tools/api-check.mjs       # three API 与 WebGLRenderer 方法
node tools/check-wiring.mjs    # 泳道图几何
```

`check-pins` 的判据是坐标，不是看图：

- 引脚必须在自己的连接器壳体内（±0.3 mm）；
- 连接器壳体必须贴住器件（中心离器件面 ≤ 4.5 mm）；
- 每个网至少两端，同网不许出现同一个脚两次；
- 沿每条线采样 26 点，落进别的器件盒子里就计数；
- 每段线的端点必须落在声明的那两个脚的 2 mm 以内。

## 三个坑

写在这里，因为都是同一类错：**几何错了画面依然"成立"，只有量坐标才发现。**

**眼睛**：规格写"单目摄像头"，但脸上不能只长一只眼。所以做成双眼：左眼是真摄像头，
右眼是同款镜筒的红外补光 + 对称装饰。镜座做成外小内大的锥形，内端埋进壳里。

**脚**：`ExtrudeGeometry` 在 XY 平面挤出，`rotateX(-90°)` 把形状 +Y 送到 -Z，而机头在 +Z ——
脚尖于是朝着屁股。修法是落地后再 `rotateY(180°)`。验证不靠看图：

```
footShellL z: -1.87 .. 5.71 | ankle z 0.15
  前伸 5.56  /  后伸 2.02  => 脚尖朝 +Z（前）OK
```

**舵机数**：规格写 15 自由度（每腿 5），模型里原来只有髋俯仰 + 膝两个，
数一数就知道对不上。补了髋偏航、踝俯仰、踝侧倾 6 个，内部图里才数得出 15 个舵机。

## 改比例

`src/model.js` 顶部有 `PROPORTION`，整机体型都从那里取。改完跑：

```bash
node tools/calibrate.mjs
node tools/check-internals.mjs
node tools/check-pins.mjs
node tools/check-print.mjs
node tools/preview.mjs cream stand out.png
```

壁厚在 `src/fit.js` 的 `WALL`；剖面的关键点与 `model.js` 的 lathe 入参逐点对应，
改剖面要两边一起改（`check-print` 会把负间隙列出来，改漏了会红）。

## 已知限制

- **不是结构 CAD**：有壁厚、有净空检查、有分件与摆向，但没有螺钉柱、卡扣、加强筋、
  拔模角与装配顺序；内腔是"外壁 - 壁厚"的旋转体近似，不是布尔挖空。
- **引脚是几何示意，不是原理图**：脚位、网名、总线类型按规格写的，没从真实
  EDA 工程导入；`check-pins` 验的是"自洽 + 不穿模"，不是电气正确。
- **走线是自动寻路的**，还有 3/2400 个采样点贴着主控板角落擦过（被 `check-pins`
  如实报出来）。真实线束会有扎带和固定点，这里只保证了拓扑与大致走向。
- **WebGL 出图没有人眼之外的证据**：本机 Edge 以 `headless` 启动会立刻正常退出
  （code 0），命令行连 `--version` 都不回，puppeteer 拿不到 DevTools 端口。
  所以验证靠 Node 端自写光栅化（`preview.mjs`）+ DOM stub + 静态体检。
  页面留了 `window.onerror` 兜底：出错会把信息打在屏幕上，而不是黑屏。
- 姿态是手调关键帧 + 时间线，不是 MuJoCo 跑出来的策略。
